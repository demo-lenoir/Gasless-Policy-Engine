# Test strategy

Phase 1 includes table-driven policy decisions, exact numeric boundaries, ABI rejection cases, snapshot validation, configuration order invariance, security-field mutation tests, and two Go fuzz targets. Phase 2 adds canonical fingerprint mutations, limits validation, and real PostgreSQL integration tests. Later suites must exercise the remaining trust boundaries and hold invariants, not mirror internal code.

| Class | Permanent cases |
| --- | --- |
| Go unit | Policy decision table for chain/target/selector/denylist, exact gas/value bounds, immutable policy version, canonical request normalization, invalid ABI/trailing bytes, stable reasons, idempotency fingerprint equivalence and conflict. |
| Go fuzz | Request parser and normalizer; canonical typed payload construction; policy evaluator determinism and no panics under bounded input. |
| PostgreSQL integration | Repeated 100-way budget, quota, and idempotency races; restart and policy-change retry; unsigned expiry/release transitions; two expiry workers; UTC midnight; cancellation and bounded retry. Phase 5 adds fork-history, finality, exact-cost settlement, unused expiry, overage, two workers, restart, consume/expire competition, and manual-intervention cases. |
| Solidity unit/fuzz/invariant | EntryPoint-only caller, separate account and paymaster signatures, wrong chain/paymaster, expiry and timestamp boundaries, exact nonce, changed sender code identity, outer/inner calldata, target/value/gas/cap mutation, malformed suffix, replay through EntryPoint, unauthorized admin, pause, `maxCost` bound, and bounded malformed-length fuzzing. |
| Cross-language vectors | Go and Solidity produce identical EIP-712 digest for fixed vectors; EntryPoint v0.9 operation hash and paymaster suffix semantics match official implementation; reserved cap bounds EntryPoint `maxCost`. |
| Local E2E | Valid gasless operation succeeds; replay, calldata/target mutation, quota exhaustion, signer failure, emergency disable/pause all reject; audit and metrics reflect outcomes. |

Phase 1 tests live in `internal/policy`; Phase 2 tests live in `internal/admission` and `internal/store`. Phase 3 adds authorization field/domain mutations and two canonical encoding fuzz targets in `internal/authorization`, signature-shape tests in `internal/signing`, PostgreSQL issuance races and crash recovery in `internal/store`, and shared JSON vector tests in Go and Foundry. `make verify-phase3` includes prior gates, ordinary and race-enabled Go tests, two fresh PostgreSQL migration runs, authorization fuzz smoke, and Foundry reference tests. Phase 4 adds `PolicyPaymasterTest` against the real pinned EntryPoint for field/domain mutations, malformed suffixes, validity boundaries, pause, zero-balance execution, deposit exhaustion, failed target execution, and bounded malformed-length fuzzing. `scripts/verify_phase4.py` runs clean PostgreSQL and Anvil twice: direct submission and pinned Alto `eth_sendUserOperation`.

Database race tests use simultaneous callers over a 32-connection pool and compare exact accepted/denied totals with ledger rows. The issuance suite runs 100 concurrent attempts for one reservation, checks one signer invocation and artifact, and reproduces a crash before commit with a stale fenced claim. Barrier-controlled tests disable issuance or expire an unsigned reservation while the signer is paused. The Solidity reference tests recompute the same committed vector's domain, struct hash, digest, signature recovery, and byte encoding. The local chain tests prove the paymaster, account, and bundled operation together. The Phase 5 deterministic fork fixture proves local checkpoint, finality, reorg, and ledger invariants; it does not establish broad chain compatibility or cryptographic RPC completeness.

`make verify-phase5` includes prior gates, ordinary and race-enabled Go tests, fresh PostgreSQL migrations, direct and Alto local execution, reverted-operation settlement, safe unused expiry, response-loss recovery, and publication scans. `TestReconciliationFinalityAndCost` checks confirmation boundaries and both execution outcomes. `TestReconciliationReorgAndReinclusion`, `TestReconciliationTerminalReorgRequiresManual`, `TestReconciliationOverageAndDeepReorg`, `TestReconciliationTwoWorkersAndRestart`, and `TestReconciliationExpiryVsInclusion` exercise fork and concurrency behavior against PostgreSQL.

Phase 6 adds HTTP request parsing, authentication, idempotent recovery and conflict, read/status/readiness projection, and PostgreSQL dry-run/replay recovery tests. `TestDeepReorgOperatorRecovery` checks that readiness stays degraded throughout replay and is restored only after convergence. `make demo` covers the actual HTTP-to-Alto-to-EntryPoint path plus one unused authorization. `make verify-phase6` includes the inherited gates, Go vulnerability scan, Docker build/runtime smoke and image scan, isolated clean-clone verification, and source-bound local release artifacts. The clean-clone check requires committed source.
