# Operations and recovery

The local service exposes `POST /v1/sponsorships`, scoped `GET /v1/sponsorships/{id}`, authenticated `GET /v1/status`, `/health/live`, `/health/ready`, and `/metrics`. `GASLESS_API_TOKEN` maps to one configured `GASLESS_CLIENT_SCOPE`; it is not a multi-tenant credential database. The process requires `GASLESS_POLICY_FILE`, `GASLESS_ADMISSION_FILE`, `GASLESS_PG_DSN`, `GASLESS_RPC_URL`, `GASLESS_LISTEN`, and `GASLESS_DEV_SIGNER_KEY`. The admission file must contain the deployed chain's issuance profile. No signer key is stored in either configuration file. Development signing is restricted to a loopback listener by default; `GASLESS_DEV_BIND_ANY=1` is only for an isolated local container network.

`/health/live` reports process liveness. `/health/ready` requires a healthy reconciliation checkpoint, responsive chain reader and signer, a consistent budget ledger, an enabled issuance control, and a deposit above the critical threshold. `/v1/status` shows the checkpoint, observed head, lag, open reservations, consumed/expired counts, global budget remaining, signer availability, and EntryPoint paymaster deposit. A low deposit remains visible as `low`; a critical deposit fails readiness. Budget and deposit are different controls. The default local thresholds are 0.1 ETH low and 0.01 ETH critical. They must be reviewed for any different chain or deployment.

## Manual intervention

On `MANUAL_INTERVENTION`, stop new issuance and retain the database, chain reader configuration, and transaction evidence. Read `/v1/status`, `reconciliation_anomalies`, `reconciliation_blocks`, `userop_observations`, and `actual_spend_ledger`. Never delete fork rows or reset counters to make readiness green. Compare chain ID, EntryPoint runtime code, genesis anchor where configured, and the affected block headers with a trusted RPC source. A second RPC may improve diagnosis but does not establish consensus.

For a `DEEP_REORG` with no terminal conflict, select a common ancestor already stored as canonical. Run `GASLESS_PG_DSN=... GASLESS_RPC_URL=... go run ./cmd/reconcile-recover -admission <profile.json> -height <block>` without `-apply`. The JSON dry run reports the checkpoint, affected blocks and sponsorships, terminal conflicts, and whether automatic replay is safe. Confirm the proposed block hash on the configured chain. Add `-apply` only after reviewing the report. The command retains old fork evidence, rolls back provisional observations, rescans bounded HTTP ranges, and restores readiness only when the saved checkpoint converges with the current head. Recovery does not spend or release a reservation based on an unresolved branch.

`TERMINAL_REORG`, `TERMINAL_EXPIRY_REORG`, `ACTUAL_COST_OVERAGE`, or conflicting canonical evidence are not automatically cleared. Compare actual EntryPoint events, deposit movement, reservation cap, the original budget period, and ledger rows. Document any compensating accounting action separately; this repository does not rewrite a finalized `CONSUMED` row. Overage retains the full observed cost and the unreleased hold. If a signed authorization is not observed, release requires both wall time and a completely scanned confirmed chain timestamp strictly beyond `validUntil`.

## Alerts and evidence

Alert on `gasless_reconciliation_lag_blocks`, manual stream state, signer errors, critical or low `gasless_paymaster_balance_wei`, and low global or per-chain budget. The service has no vendor-specific alert sink. Metric labels contain bounded decisions/reasons only; exact Wei and request identities belong in PostgreSQL and audit events. Prometheus Wei gauges are approximate floating-point views and never drive admission.
